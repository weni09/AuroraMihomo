## 概念与数据流

最终交给 mihomo 内核的 `config.yaml` 由三层合并而成：

```
Base（本地基础配置）      你在「配置中心」填的内容
        +
Remote（远程层）          订阅 / 组合 / 文件模板 / 外部链接，二选一
        +
Override（覆写层）        模板文件里的 YAML 覆写或 JS 脚本
        ↓
   冲突检测与策略裁决
        ↓
   data/config.yaml  →  mihomo 内核
```

几个容易混淆的点：

- **订阅的「刷新缓存」不会改最终配置**。它只更新该订阅自己的节点缓存，供分享链接与预览使用。要让改动进内核，得去配置中心点「保存并应用」或「立即拉取并合并」。
- **分享链接与最终配置是两条独立的路**。分享链接实时渲染订阅/组合的节点，不经过三层合并；最终配置才是内核加载的东西。
- **合并前自动备份**。每次合并都会把旧配置存进 `data/backups/`（保留 10 份），校验失败自动回滚。

## 登录

只有一个密码框。初始密码在首次启动时生成：

```bash
cat data/initial_password.txt                        # 二进制部署
docker exec auroramihomo cat /data/initial_password.txt   # Docker
```

登录后请立即在「系统设置 → 管理员密码」改掉，并手工删除该文件——它不会自动删除。

5 分钟内失败 5 次会锁定 15 分钟，页面会显示剩余时间。

## 控制台

只读概览页，五张状态卡：

| 卡片 | 含义 |
|---|---|
| 内核状态 | 运行中 / 已停止 |
| 内核版本 | 由 `mihomo -v` 探测 |
| 代理节点数 | 第一个组合订阅渲染出的节点数 |
| 上次订阅更新 | 所有订阅中最近一次刷新时间 |
| 配置状态 | 正常 / 未配置；有未解决冲突时额外显示条数 |

下方是后台任务列表（配置合并、内核重载、版本检查）与实时内核日志（最多 100 行）。

右上角徽标显示实时通道状态：连接中 / 已连接 / 已断开 / 连接异常 / 服务端重启中。它走 WebSocket，断线会自动指数退避重连。

> 「N 项冲突待处理」目前只是提示，**界面上没有逐条解决冲突的入口**。详见[合并策略与冲突](#合并策略与冲突)。

## 内核管理

五个操作：

| 按钮 | 作用 | 是否二次确认 |
|---|---|---|
| 启动 | 拉起 mihomo 进程 | 否 |
| 停止 | 结束进程 | 是（会中断所有代理连接） |
| 重启 | 停止后重新拉起 | 是 |
| 重载配置 | 让内核重新读 `config.yaml`，不重启进程 | 否 |
| 更新内核版本 | 下载最新 mihomo 并替换 | 否（设置页的同名操作有确认） |

改完配置后用「重载配置」通常就够了，比重启温和。少数配置项（如 TUN 相关）内核要求重启才生效。

## Sub-Store 管理

四个标签页：单个订阅、组合订阅、模板文件、分享管理。

### 单个订阅

**新建时要填什么**

| 字段 | 必填 | 说明 |
|---|---|---|
| 订阅名称 | 是 | 如「机场A」 |
| 自定义 User-Agent | 否 | 部分上游按 UA 返回不同格式，如 `ClashForWindows/0.20.39` |
| 节点来源 | — | 二选一：远程订阅地址 / 手动粘贴节点 |
| 订阅地址 | 远程模式必填 | `https://...` |
| 节点内容 | 粘贴模式必填 | 每行一条分享链接（`ss://` `vmess://` `vless://` `trojan://` `hysteria2://` 等），也可直接粘 Base64 订阅或 Clash YAML |
| 启用此订阅 | — | 默认勾选。禁用后不参与组合与配置合并，分享链接也失效 |
| 独立处理管道 | 否 | 见下节。先于组合管道执行 |

手动粘贴的节点无需回源，保存即可用。

**列表上能做什么**

- **复制外部分享链接**：名称下方的下拉，15 种格式任选，点哪个复制哪个
- **预览**：看处理前后的节点对比，不写库
- **刷新缓存**：回源拉最新节点。**只更新缓存，不改最终配置**
- **分享设置**：改名、设有效期、重置凭据、撤销
- **删除**：会二次确认

流量列显示「已用 / 总量」与进度条（≥70% 转琥珀、≥90% 转红），下方是到期时间与剩余天数。这些信息来自上游返回的响应头，不是所有机场都提供。

> 「自动更新间隔」字段已从界面移除。订阅不再各自定时回源，刷新时机统一由配置中心的定时拉取或手动操作决定。

### 处理管道与 12 个算子

管道按从上到下的顺序执行。订阅自己的管道先跑，然后才是组合的管道。

| 算子 | 参数 | 作用 |
|---|---|---|
| **常用配置** | 9 个下拉，默认都是「不改」 | 批量改节点属性：过滤非法节点、UDP 转发、跳过证书验证、TCP Fast Open、VMess AEAD、连接复用、阻止 QUIC、ECN、IP 版本。不适用于当前协议的选项自动跳过 |
| **节点过滤** | 保留/剔除 + 正则 | 按节点名正则整个保留或剔除。如 `HK\|HongKong` |
| **正则改名** | 匹配 + 替换 | 正则替换节点名 |
| **自动加国旗** | 无 | 按名字给节点加国旗 emoji。支持 HK TW JP SG KR US UK DE FR CA AU RU IN TR NL |
| **覆盖节点属性** | 键 + 值 + 值类型 | 逐节点写入属性，如 `udp=true`、`skip-cert-verify=true`。值类型可选文本/布尔/数字 |
| **按地区筛选** | 保留/剔除 + 地区列表 | 每行一个地区码，自动识别中英文与旗帜 emoji |
| **剔除无效节点** | 无 | 自动剔除「剩余流量」「到期时间」「官网」这类机场信息假节点 |
| **正则删除字符** | 匹配 | 只删名称里的匹配片段，不删节点本身。如 `【[^】]*】` |
| **名称排序** | 升序/降序 | 按名称排序 |
| **关键词排序** | 关键词列表 | 按关键词优先级排，未命中的按名称排到末尾 |
| **域名解析为 IP** | 可选优先 IPv6 | 把节点域名解析成 IP。解析失败保留原域名，不中断管道。超时 3 秒 |
| **⚡ 注入 JS 脚本** | JS 代码 | 传入 `proxies` 数组，返回修改后的数组。执行超时 5 秒 |

JS 脚本的骨架：

```javascript
function operator(proxies) {
  // 在这里修改 proxies
  return proxies
}
```

它能力最强也最容易出错，界面上用实色按钮与其他算子区分。

### 组合订阅

把多条订阅聚合成一个，再统一处理。

| 字段 | 必填 | 说明 |
|---|---|---|
| 组合名称 | 是 | |
| 选择基础订阅源 | 至少一个 | 复选，点击切换 |
| 处理管道 | 否 | 同上 12 个算子 |
| 启用 | — | 默认勾选。关闭后分享链接立即失效 |

组合本身没有输出格式设置——格式由分享链接的 `?target=` 决定。

**15 种输出格式**：默认（Mihomo YAML）、Clash / Mihomo、Base64 订阅、明文分享链接、Surge、Surge Mac、Loon、QuantumultX、sing-box、V2Ray、纯 JSON、Stash、Surfboard、Shadowrocket、Egern。

> 分享设置弹窗里的格式下拉只有 10 项，是常用子集。要用全部 15 种，走列表页的「复制外部分享链接」下拉，或手工在链接后加 `?target=`。

### 模板文件

两种用途，由「配置类型」决定：

**① 文件（原样输出）** — 存规则片段、Surge 模块之类，通过直链原样对外提供。格式可选纯文本 / JavaScript / JSON / YAML / INI，保存前会按格式做真实校验（JSON/YAML 解析、INI 逐行检查、JS 编译）。

**② Mihomo 配置（模板转换）** — 由所选订阅的节点套用模板，产出可直接订阅的配置。需要指定节点来源（单条订阅或组合），并选模板语言：

| 模板语言 | 说明 |
|---|---|
| **YAML 覆写**（新建默认） | 在自动生成的基础配置上打补丁。深度合并：标量/对象递归，数组默认整体替换。支持 `+key` 前插、`key+` 追加、`key!` 强制覆盖 |
| **Go 模板** | 从零手写整份配置。可用 `.Nodes` 数组，每项含 `Name` `Type` `Server` `Port` `UDP` `Extra` |
| **JS 脚本覆写** | 必须定义 `function main(config)` 并 return，`config` 是自动生成的基础配置对象 |

后两者的区别：Go 模板要自己写全 `proxies`/`proxy-groups`/`rules`；YAML 覆写与 JS 覆写是增量修改，对齐官方 Sub-Store 的「覆写」用法。

> **兼容行为**：新建文件默认 YAML 覆写，但打开旧文件时若没记录模板语言，会兜底为 Go 模板——因为后端对存量数据也按 Go 模板解释。不要随手改成 YAML，那会静默改变旧文件的渲染结果。

**正文来源**可以是本地编辑、远程拉取，或两者合并（本地在前 / 远程在前）。远程地址每行一个，以 `#` 开头的行被忽略便于临时停用。多个地址并发拉取但按书写顺序拼接。

远程失败处理三选一：失败即报错（推荐）/ 跳过并提示 / 静默跳过。**选跳过时缺失的内容没有明显提示，客户端可能拿到不完整的配置。**

文件直链是 `/api/v1/file/<token>`，**不支持 `?target=` 与 `?filter=`**（原样输出或固定模板渲染，没有这个概念）。

### 分享管理

集中管理订阅、组合、文件的对外链接。凭据在创建实体时就自动生成，这里做的是管理已有分享。

| 操作 | 说明 |
|---|---|
| 设置 | 改分享展示名（留空显示来源名）、设有效期（快捷 7/30/90 天或永不过期） |
| 重置链接 | 生成新凭据，**旧链接立即失效**。用于凭据外泄后的补救 |
| 撤销 | 清空凭据，访问者立即无法获取。实体本身保留，可再「重新启用」 |

状态徽标：生效中 / 已撤销 / 已过期 / 来源已停用。

链接格式：

```
/api/v1/share/<token>              # 订阅与组合
/api/v1/share/<token>?target=surge # 指定格式
/api/v1/share/<token>?filter=香港   # 临时筛选
/api/v1/file/<token>               # 文件模板
```

**这些链接无需登录，凭据即链接本身。** 请勿在分享内容里放敏感信息；怀疑外泄就重置。

## 配置中心

### 远程订阅来源

远程层只能选一个来源：

| 类型 | 说明 |
|---|---|
| 不使用（仅本地配置） | 默认。最终配置等于本地填的内容 |
| 本地订阅：单条 | 用某一条订阅 |
| 本地订阅：组合 | 用某个组合（推荐，能用上管道处理） |
| 本地文件模板 | 只能选「配置类型 = Mihomo 配置」的文件 |
| 外部订阅链接 | 别人分享给你的地址。不存为订阅、不参与定时刷新，每次合并都重新拉取 |

停用的订阅/组合仍会列出但不可选，并标注原因——直接隐藏会让人困惑于「我明明建了这个组合，为什么选不到」。

**定时拉取**：勾选后填 Cron，或用四个预设（每 30 分钟 / 每小时 / 每 6 小时 / 每天 4:00）。关闭则只能手动拉取。

两个按钮的区别：**保存**只记来源设置；**立即拉取并合并**才会真的回源并重新生成最终配置。

### 本地基础配置 11 组

所有字段留空 = 不设置该项，由内核回落默认值。placeholder 显示的是官方默认，不是已生效的值。

| 分组 | 管什么 |
|---|---|
| **通用设置** | 运行模式、日志级别、允许局域网、IPv6、进程匹配、TLS 指纹、TCP 并发、连接保活、入口认证（`user:pass` 每行一条）、局域网 IP 白/黑名单 |
| **端口设置** | `port` `socks-port` `mixed-port` `redir-port` `tproxy-port`。推荐只开 `mixed-port` |
| **外部控制** | `external-controller`（默认 `127.0.0.1:9090`）、`secret`、面板挂载路径。**对外暴露时务必设 secret** |
| **GeoData 规则库** | GeoIP/GeoSite 数据源与自动更新间隔 |
| **运行状态持久化** | 记住手选节点（建议开启）、记住 fake-ip 映射 |
| **域名解析** | DNS 全部行为：enhanced-mode（推荐 fake-ip）、fake-ip 段与过滤、各类 nameserver、respect-rules 等。**用 TUN 时必须开 dns.enable** |
| **虚拟网卡** | TUN 的 enable / stack / auto-route / dns-hijack / mtu / strict-route 等 |
| **域名嗅探** | 从流量还原域名。注意：只开总开关不配 `sniffer.sniff` 的话嗅探不会生效 |
| **策略组** | YAML 数组定义本地策略组，与订阅中同名组合并 |
| **基础路由规则** | 每行一条，会被置顶插入最终配置，顺序即优先级 |
| **高级参数** | 兜底所有未建模的顶层键：`listeners` `proxy-providers` `sub-rules` `tls` `experimental` `hosts` `tunnels` `ntp` 等 |

**两个必须知道的交互**：

1. **清空「策略组」或「高级参数」编辑器不等于清空配置**。编辑过程中必然经过「空」这个中间态，若当场生效会把内容删光，所以空值被忽略。真要清空得点字段下方的「清空此项」按钮。
2. **数字字段清空会删除该键**，而不是写 0。因为 `port: 0` 与「不设置 port」语义完全不同。

三个保存按钮：

- **放弃修改（重新加载）** — 丢弃未保存改动
- **保存基础配置** — 只存本地层
- **保存并应用** — 存完立即重新生成最终配置（不拉远程）

若基础配置加载失败，表单会整体隐藏并显示错误——这是防止用空表单覆盖服务端真实配置。

### 合并策略与冲突

在「系统设置 → 配置合并策略」设定本地与远程冲突时采用哪一方：

| 冲突类型 | 可选策略 |
|---|---|
| 节点冲突 | 本地优先（默认）/ 远程优先 / 自动合并 / 手动确认 |
| 规则冲突 | 本地优先（默认）/ 远程优先 / 手动确认。**没有「自动合并」**，因为规则有先后顺序语义，无法安全地自动合并 |
| DNS 冲突 | 本地优先（默认）/ 远程优先 |
| 虚拟网卡冲突 | 本地优先（默认）/ 远程优先 |
| 其余通用参数 | 本地优先（默认）/ 远程优先 |

「其余通用参数」覆盖运行模式、各监听端口、Geo 数据、外部控制、认证、嗅探等所有其他顶层项。

**无论选哪种策略，订阅里没声明的项一定沿用你的本地设置，不会被清空。**

> **重要限制**：选择「手动确认」后，控制台只会显示「N 项冲突待处理」的条数，**界面上没有逐条选择的入口**。除非你直接调用 API，否则建议不要用「手动确认」。

## 配置差异

三栏只读对照：**本地配置** / **最终配置** / **远程订阅**，各自可下载成 yaml。

排查「为什么我改的东西没生效」时先看这里：对比本地栏与最终栏，就知道是被远程覆盖了还是压根没保存。

改动请回配置中心，本页只读。

## 运行日志

两个标签：

- **内核日志** — mihomo 子进程的输出，分 输出 / 错误 / 系统
- **应用日志** — 本程序自己的日志，可按级别筛选（错误 / 严重 / 慢调用 / 信息 / 调试）

前端保留 500 行，自动跟随滚动；手动上滑会暂停跟随并提示，滑回底部恢复。

「清空」只清当前标签。清应用日志时会同时清后端内存缓冲，**但不动磁盘上的日志文件**。

磁盘日志在 `data/logs/aurora.log`，8MB × 5 份滚动，另有按天数的定时清理（见系统设置）。

## 系统设置

**这一页有四个独立的提交入口**，不是「改完点一次保存」：

| 区块 | 如何生效 |
|---|---|
| 管理员密码 | 自己的「修改密码」按钮 |
| 透明代理 | 开关即时生效 |
| 配置合并策略 | 自己的「保存合并策略」按钮 |
| 自动更新 / 下载出网 / 日志 | 页面底部的「保存设置」按钮 |

### 管理员密码

当前密码 + 新密码（至少 8 位）+ 确认。

### 组件状态

显示 mihomo 与 Zashboard 的安装状态、版本、路径，三个按钮：检查更新（只读版本不下载）、更新 Mihomo（有确认）、更新 Zashboard（有确认）。

内核版本由 `mihomo -v` 探测。面板是纯静态资源，本地无法反查版本，只记录经本平台更新的那一次——手工放入或旧版本装的面板会显示「版本未知」。

### 自动更新

| 项 | 默认 | 说明 |
|---|---|---|
| 启用自动更新 | 关 | mihomo 与 Zashboard |
| Cron 表达式 | `0 0 4 * * *` | 支持 5 位或 6 位（6 位含秒） |

### 透明代理

见 [README 的透明代理小节](../README.md#透明代理) 与[透明代理文档](AuroraMihomo-Transparent-Proxy.md)。

要点：环境不具备时开关禁用并说明缺什么；启用后须在 90 秒内确认，否则自动回滚；折叠的「环境检测详情」是排障依据。

### 下载与更新出网

| 项 | 默认 | 说明 |
|---|---|---|
| 优先经由本地 Mihomo 代理出网 | 开 | 内核在跑时，下载与版本查询都先走它。拿到的是 GitHub 官方原始文件，不用担心第三方镜像返回被篡改或截断的内容 |
| 下载源（每行一个） | 8 个内置源 | 按顺序尝试，失败自动回退 |

下载源的写法：完整前缀（如 `https://mirror.example.com`，会拼在官方地址前）或含 `%s` 的模板。**裸域名会被忽略**，jsdelivr 会被跳过（它只镜像仓库内文件，代理不了 Release 资产）。

检查更新走 `api.github.com`，不使用这些源——GitHub REST API 没有可用镜像，网络不通时靠上面的 mihomo 代理兜底。

### 日志

| 项 | 默认 | 范围 |
|---|---|---|
| 日志保留天数 | 7 | 1–365 |
| 启用定时清理 | 开 | 关闭后只靠大小轮转（8MB × 5 份） |
| 清理时间（Cron） | `0 30 3 * * *` | 5 位或 6 位，保存后即时生效 |

清理只影响已归档的历史文件，当前正在写的那份由大小轮转管理。

## Zashboard 面板

内嵌的 mihomo 官方面板，可看实时连接、切换节点、测延迟。

进入页面时后端会用当前内核的 `external-controller` 拼出带认证的地址，**面板自动对接，无需手填**。

打不开的常见原因：

- 内核没启用 `external-controller` → 去「配置中心 → 外部控制」设成 `127.0.0.1:9090` 后重新合并配置
- 面板资源没装 → 去「系统设置」执行「更新 Zashboard」

也可通过 `http://<地址>/ui/` 直接访问。

## 配置文件与环境变量

配置文件默认 `backend/api/etc/aurora-api.yaml`，容器内是 `docker/aurora-api.docker.yaml`。

### 配置文件主要项

| 项 | 默认 | 说明 |
|---|---|---|
| `Host` / `Port` | `0.0.0.0` / `8899` | 监听地址与端口 |
| `Timeout` | 300000 | 单请求处理超时（毫秒）。合并配置、下载内核远超默认 3 秒 |
| `Server.ReadHeaderTimeoutSec` | 10 | 防慢速连接（Slowloris）长期占用 |
| `Server.ReadTimeoutSec` | 60 | |
| `Server.WriteTimeoutSec` | 360 | **必须大于 `Timeout`**，否则长耗时请求会在写响应阶段被掐断 |
| `Server.IdleTimeoutSec` | 120 | |
| `TrustedProxies` | `[]` | 可信反代的 IP/CIDR。留空则一律用真实 RemoteAddr |
| `DataSource` | `./data/aurora.db` | SQLite 路径 |
| `Mihomo.BinaryPath` | 空 | 留空则用数据目录下的默认位置 |
| `Mihomo.ConfigDir` | `./data` | 数据目录 |
| `AppLog.MemoryLimit` | 1000 | 内存保留条数，供界面查看 |
| `AppLog.ToFile` | true | 落盘便于回溯重启前的现场 |
| `AppLog.MaxFileMB` / `MaxBackups` | 8 / 5 | 磁盘占用上界约 40MB |
| `AppLog.IncludeAccessLog` | false | 打开后满屏是访问记录，业务日志会被冲走。排查请求链路时再临时开 |
| `Updater.UseMihomoProxy` | true | 优先经本地内核代理出网 |
| `Updater.CDNProviders` | 8 个源 | 顺序即优先级 |

**`TrustedProxies` 的两个坑**：部署在反代之后却不填，所有请求会被归到反代 IP 上（一个用户登录失败会影响其他人）；填成 `0.0.0.0/0` 则等于允许任何人伪造头部绕过限流。

### 环境变量（优先级高于配置文件）

| 变量 | 说明 |
|---|---|
| `AURORA_JWT_SECRET` | JWT 签名密钥。生产建议显式设置，否则首次启动随机生成并存库 |
| `AURORA_JWT_EXPIRE` | 令牌有效期（秒），默认 86400 |
| `AURORA_DATA_SOURCE` | SQLite 路径 |
| `AURORA_CONFIG_DIR` | 数据目录 |
| `AURORA_MIHOMO_BINARY` | mihomo 二进制路径 |
| `AURORA_HOST` / `AURORA_PORT` | 监听地址与端口 |
| `AURORA_AUTO_UPDATE` | 是否启用自动更新（true/false） |
| `AURORA_AUTO_UPDATE_CRON` | 自动更新 cron（6 段，含秒） |
| `AURORA_GITHUB_API` | GitHub API 地址，可指向自建镜像 |
| `AURORA_CDN_PROVIDERS` | CDN 源列表，逗号分隔 |
| `AURORA_USE_MIHOMO_PROXY` | 是否优先经内核代理出网 |

## 常见问题

**改了配置为什么没生效？**

去「配置差异」页对比本地栏与最终栏。三种可能：没点「保存并应用」；被远程层覆盖了（调整合并策略）；内核没重载（去内核管理点「重载配置」）。

**订阅刷新了但节点没变？**

订阅的「刷新缓存」只更新自身缓存，不改最终配置。要进内核得去配置中心「立即拉取并合并」。

**分享链接打不开？**

检查四点：分享是否被撤销、是否已过期、来源订阅/组合是否被停用、链接是否完整（凭据很长，容易复制不全）。

**策略组/高级参数被我清空了，保存后却还在？**

这是有意的保护。清空编辑器不生效，要点字段下方的「清空此项」按钮。

**内核下载一直失败？**

在「系统设置 → 下载与更新出网」调整源顺序，或参照 README 的离线安装手工放置内核到 `data/bin/mihomo`。

**mihomo 官方发布的 Linux 包是什么格式？**

`.gz`（gzip 压缩的裸二进制，不是 tar 归档），只有 Windows 是 `.zip`。手工解压用 `gunzip -c xxx.gz > mihomo`。

**TUN 开了但局域网设备没走代理？**

容器部署最常见的是网络模式问题——桥接网络里的规则只对容器自己生效，必须用 `network_mode: host`。另外查「系统设置 → 透明代理 → 环境检测详情」，它会明确指出缺 capability、缺设备还是缺 host 网络。

**忘记管理员密码？**

见 [README 的排障小节](../README.md#排障)。
