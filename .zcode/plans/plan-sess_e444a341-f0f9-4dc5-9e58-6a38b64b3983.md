## 目标
把前端所有业务页面里的裸原生控件（button/input/select/textarea/checkbox/radio）替换为 shadcn-vue 组件，让约束 2（UI 必须用 shadcn-vue 组件）从"不符合"变成"符合"，同时不破坏现有交互（联动显隐、草稿态、防抖提交、危险操作确认等）。一次性全部迁移，最后统一验收。

## 技术选型（已确认/需说明的默认决策）

- **按钮 variant 映射**：`.btn-accent`（emerald）→ shadcn `secondary`；`.btn-danger`（描边红）→ shadcn `destructive`（红色实底）。视觉会变（绿变灰、危险按钮从描边变实底），用户已确认接受。
- **弹窗**：`ModalDialog.vue` 改为基于 shadcn `Dialog`/`DialogContent`/`DialogHeader`/`DialogTitle` 的薄封装，尽量保留现有 props（`open`、`title`、`maxWidth`）与 `header`/默认 slot 的调用方式，减少 5 个调用点（ShareDialog、PreviewPanel、CollectionsView、SubscriptionsView、FilesView）的改动量；PreviewPanel 需要叠加在表单弹窗之上的场景，允许视觉/交互做适当简化（不追求像素级还原原有 z-index 55 的手搓层级）。
- **下拉选择**：30+ 处 select 中大多是固定值域的简单下拉（如 local/remote/merge/manual、target 格式）。用 shadcn-vue 的 `native-select`（样式化的原生 `<select>`，也是官方 shadcn-vue 组件）而不是完全自定义的 `select`（Listbox 式，markup 改动量数倍）。这样既满足"必须用 shadcn-vue 组件"的强制约束，又把改动量控制在合理范围，同时原生 `<select>` 在移动端触屏体验更好。
- **触屏热区**：现有 `main.css` 里 `@media (pointer: coarse)` 对 `.btn`/`.btn-sm`/`.tap-target` 做了 44px 热区强制。迁移后改为对 shadcn Button 的渲染根元素（`[data-slot="button"]`）生效，不需要业务代码逐个加 class。
- **依赖安装**：`npx shadcn-vue add button input select native-select textarea checkbox radio-group dialog label`，CLI 会自动装好 `@vueuse/core`、`reka-ui`（已在依赖里）等。

## 执行阶段（一次性推进，分阶段是为了控制风险顺序，不是分批确认）

**阶段 0：装组件 + Button variant 收尾**
- 跑 CLI 装 `button/input/native-select/textarea/checkbox/radio-group/dialog/label` 到 `src/components/ui/`
- 调整 `main.css` 触屏热区选择器，指向 `[data-slot="button"]`
- 迁移完成后删除不再被引用的 `.btn-*` CSS（迁移完 grep 确认无引用再删）

**阶段 1：ModalDialog 弹窗地基**
- 把 `ModalDialog.vue` 内部实现换成 shadcn `Dialog` 系列组件，去掉手写的焦点陷阱/Escape监听/滚动锁定（Dialog 自带）
- 保持对外 API 基本不变，5 个调用点（ShareDialog/PreviewPanel/CollectionsView/SubscriptionsView/FilesView）仅做必要的适配性改动

**阶段 2：简单页面（验证 Button/Input/Label 迁移模式）**
- `LoginView.vue`、`NotFoundView.vue`、`MihomoView.vue`、`LogsView.vue`、`ZashboardView.vue`
- `App.vue`（抽屉按钮、退出登录按钮）、`ThemeToggle.vue`（`<button role="radio">`→shadcn Button/ToggleGroup 风格保留三态语义）、`ToastHost.vue`（关闭按钮）、`PreviewPanel.vue`（tab/复制/关闭按钮）

**阶段 3：中等复杂表单**
- `SharesView.vue`、`ShareDialog.vue`（button/input/select）
- `CollectionsView.vue`（名称输入、启用开关、多选订阅源 checkbox 组，保留 `role="group"` 语义用 shadcn Checkbox 组重建）
- `SettingsView.vue`（密码输入×3、cron输入、5个策略select、2个checkbox）
- `SubscriptionsView.vue`（radiogroup 联动 URL输入/CodeEditor、启用checkbox、格式select）

**阶段 4：高复杂度动态表单（逐分支迁移，最容易出问题，放最后）**
- `PipelineEditor.vue`：12 种算子类型的 v-else-if 分支表单逐个替换，保持 `op.payload` 动态绑定与增删逻辑不变
- `FilesView.vue`：`configType`/`sourceMode`/`mergeSources` 三组联动显隐逻辑要在替换后逐一验证仍生效
- `ConfigView.vue`：schema 驱动的动态字段渲染（switch/select/textarea/yaml-object/string-array/number/text/code 八种类型分支），叠加草稿态与防抖提交，风险最高，改完要重点回归

**阶段 5：清理与验收**
- grep 确认全项目 views/components（非 ui/ 目录）内无残留裸 `<button>`/`<input>`/`<select>`/`<textarea>`/checkbox/radio（CodeMirror 的 `<textarea>` 属于第三方库内部实现，不算业务裸控件，排除）
- 删除 `main.css` 中不再被引用的 `.btn-*` 类
- 跑 `cd frontend && npx vue-tsc --noEmit -p tsconfig.app.json`、`npx eslint . --no-fix`、`npm test`、`npm run build`，全部通过
- 用浏览器抽查关键页面（登录页、组合订阅、设置页）在浅色/深色主题下的视觉，以及移动端窄屏下的可用性，作为人工目测补充（自动化检查不能覆盖视觉/主题层面）

## 风险与说明
- 这是一次跨 15+ 文件、71+ 处控件的大改动，过程中会持续用 TodoWrite 跟踪各文件状态。
- 按钮视觉会有变化（绿→灰、危险按钮描边→实底），这是本次迁移的既定权衡，不是缺陷。
- ConfigView/FilesView/PipelineEditor 的动态表单逻辑改动风险最高，会在阶段4单独做仔细的手动代码复核（对照迁移前后的 computed/v-if 条件是否一致），而不只是过一遍类型检查。
- 最终会给出一份变更文件清单和验证结果汇总，而不是每个文件都单独找你确认（按你选择的"一次性做完再验收"）。
